# 版本与产出

在冻结交付物、版本线、当前版冲突或正式回退时读取本文件。

## 区分活文档与冻结交付物

| 类型 | 典型材料 | 维护方式 |
| -- | -- | -- |
| 活文档 | README、台账、执行清单、Backlog、权威定义、工作笔记 | 原位维护；历史优先交给版本控制系统 |
| 冻结交付物 | 正式报告、送审方案、定稿设计、发布包、用户要求保留的快照 | 新增版本，不覆盖已冻结版本 |

不要按“用户能看见”或“文件可传阅”判断是否升版。只有同时满足下列多数条件时，才将材料视为冻结交付物：

- 已达到可独立验收的稳定状态。
- 后续需要按名称或版本精确引用。
- 覆盖后会破坏审阅、交付或回退证据。
- 用户或流程明确要求冻结。

## 管理冻结版本

- 使用项目既有命名；没有约定时可用 `名称-vN.扩展名`。
- 被新版本取代的同线旧版移入该线的历史位置。
- 整条方案或整份材料被放弃时整体归档，不把正常旧版混入废弃归档。
- 移动而非复制，避免同一版本同时出现在多个位置。
- 每条产出物线独立演进、独立验收、独立编号。
- 第二类冻结交付物真正出现时再拆分产出物线。

## 当前版指针

仅为冻结交付物维护当前版指针：

```text
产出物线 | 当前版文件 | 状态 | 对应关系
```

- 当前版文件列只放路径。
- 备注、来源和跨线映射写在对应关系列。
- 每条线最多一个当前冻结版本。
- 活文档不进入该表。

## 状态表达

按项目语境选择少量可观察状态，避免“差不多”“基本完成”：

- 文档、研究、设计：探索 → 候选 → 已定稿 → 已交付。
- 执行型产出：已定义 → 进行中 → 验证通过 → 已交付。
- 环境型成果：本地通过 → 受控环境通过 → 已上线验收。

不要为了统一状态词而歪曲项目事实；状态必须说明验证边界。

## 版本控制系统

有版本控制系统时：

- 代码、配置、活文档和脚本使用提交历史，不使用文件名 `-vN`。
- 按逻辑单元提交，不按每个微小动作提交。
- 仅在稳定关口打标签。
- 查看状态和定向差异，避免把全仓历史载入上下文。

没有版本控制系统时，只有难以恢复且需要明确回退的材料才使用文件版本。不要让轻量项目因缺少 Git 而自动复制所有工作文件。

## 冲突与回退

- 多个疑似当前版并存时，不凭文件名中的“final”“最新”自行裁决。
- 比较时间、内容、引用关系和用户确认记录，给出候选与推荐。
- 回退时保留后续版本的历史，不将回退伪装成它们从未发生。
- 已冻结材料发现问题时，先报告差距并请用户选择修订、降级、顺延或接受风险。
