# 行为评估

评估目标不是确认 AI 能否执行完整项目流程，而是确认它能选择最小充分流程。

## 场景

| 场景 | 重点 |
| -- | -- |
| S1 一次性简单任务 | 不应创建项目骨架 |
| S2 轻量日常迭代 | 不应触碰管理文件或升级活文档版本 |
| S3 项目基线变化 | 只更新权威源和一条关键决策 |
| S4 外部条件未确认 | 应先核验条件，不投入完整执行 |
| S5 高影响日常任务 | 强化验证，但不升级治理模式 |
| S6 里程碑陷阱 | 未达标时先裁决，不擅改冻结交付物 |
| S7 项目交接 | 生成最小交接上下文，不复制完整历史 |

## 使用

```text
python build_fixtures.py
```

每个场景会生成相同的 `before/` 与 `after/`。将用户消息原样交给被测 agent，让它只在 `after/` 工作，然后运行：

```text
python score_run.py --case S2 --before generated/S2/before --after generated/S2/after
```

机器评分检查文件级约束；`cases.json` 中的 `review_expectations` 用于人工核对语义行为。既要检查应做动作，也要检查禁止动作。

## 关键指标

- 管理文件触碰数量。
- 不必要的新文件和版本升级。
- 冻结交付物是否被越权修改。
- 权威源与关键决策是否保留。
- 是否把验证强度误判为治理模式。
- 是否在外部条件未确认时提前投入完整执行。

完整行为回归需要真实 agent 运行；本仓库的单元测试只验证夹具、评分器和脚本确定性。
