# 共享输入与多成果

## 从实际依赖识别共用层

适用于多个报告、图表、Demo 或需求成果共享部分输入的项目。先看现有输入、处理流程、引用和产出关系，不要求用户先设计一套完整的“基础口径”。

区分三层，避免把一份报告的方法推广到整个项目：

- 共享输入：原始数据、清洗数据、素材、访谈或证据，以及能区分内容状态的来源/版本。
- 共享约定：实际跨成果使用且已确认的筛选、字段、单位、时间范围或事实。推断出来的共用规则先标暂定；歧义影响结论才询问。
- 成果专属设定：本报告的受众、问题、样本子集、方法、假设和结论，允许各不相同。

只为实际需要管理的依赖保留可追溯记录。优先复用已有数据字典、查询、报告元数据和目录索引；无须同时新建关系表、口径表和版本表。必要时用一张小表：成果 → 输入/处理版本 → 共享约定 → 专属方法 → 状态。

## 变更按依赖传播

1. 确定变化发生在输入、共享约定、专属方法还是文字展示。
2. 沿实际依赖找受影响成果，说明未影响的理由；不要因“同项目”全部更新。
3. 更新受影响活文档或计算，复用有效清洗结果、公共计算及检查证据。
4. 若依赖关系不明，先做针对性的检查，仍无法确认则标记影响待定；不要凭文件名判定安全。

示例：某份报告只改结论段措辞，不使另一份报告的数据失效；某个两份报告共同依赖的清洗过滤规则改变，则两份报告相关计算都需复核，但各自不相干的文字与方法无需重做。

## 冻结成果与源变化

不同分析方向属于不同成果线，而不是一个报告的递增版本。正式冻结时，记录足够复现的输入状态和口径引用，未必需要复制全部数据或改文件名。

共享数据更新后，不静默改写旧的冻结报告。标记影响，按授权生成新修订或保留原快照；只调整受影响成果的当前指针。一个“当前”目录含多个不同报告是正常情况。路径、外部引用和协作者依赖也是需保护的成果关系。
