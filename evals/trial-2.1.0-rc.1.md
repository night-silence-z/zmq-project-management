日期：2026-09-07。范围：2.1.0-rc.1 本地候选版。这些试跑发生在 GitHub 预发布前，记录保留当时的验证范围。

## 已验证

- 官方 skill-creator quick_validate 通过；UI 元数据由配套生成器生成。Windows 下生成/验证使用 Python UTF-8 模式。
- 23 项自动化检查通过：原完整套件 22 项通过后，仅对夹具编码修正重跑受影响的 9 项 eval 测试（含新增哈希一致性检查）。未声称运行远端 CI。
- 检查涵盖：脚手架默认不写自举文件、不覆盖非空项目、路径范围、通用模板、定向健康检查、自定义入口、多个独立成果、外部链接边界、评分器拒绝无操作/删除伪装完成。
- 4 个独立代理场景已同时通过机器约束和维护者的实际结果审阅：

| 场景 | 观察到的行为 | 管理文件变化 |
| -- | -- | -- |

## 证据复用场景的夹具修正

S11 初次夹具的哈希按 LF 文本生成，但 Windows 写文件时转成 CRLF，造成证据与实际字节不匹配。该次中止，不计为 skill 行为通过或失败。生成器改为确定的 LF 写入，并增加实际文件字节与证据哈希一致性测试。

随后用新隔离目录和无前序诊断上下文的独立代理重跑 S11，通过机器约束与实际回复/操作范围审阅；没有修改 skill 来迎合错误夹具。

## 局限与下一步

11 个场景是评估资产，不代表全部完成了代理试跑。样本小，未运行真实 20–30 轮产品迭代、完整 PRD 产出或真实外部消息发送；不据此声称耗时降低比例或授权提示全部消失。真实项目试用继续观察：

- 该问的目标问题是否主动、连续且有用，清晰的局部任务是否直接执行。
- 当前需求是否保持有效状态，能否区分用户决定、AI 暂定和用户验收。
- 检查是否围绕用途与影响，已有效证据是否复用。
- 同一范围内的明确授权是否沿用，实际用户试用清单是否有帮助。

按 skill-creator 的方法，本次用行为结果检查流程选择，不把生成措辞当成规范断言。安装时保留旧版完整备份，并对候选与本机 19 个文件逐一校验 SHA256 一致性。
