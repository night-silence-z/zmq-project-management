# 版本与产出

## 活文档和冻结快照

README、当前需求、任务清单、数据字典、工作稿通常原位演进。历史优先由版本控制或现有系统保留；没有历史能力时按确有追溯价值的变化保留修订说明，不每轮复制带版本号的文件。

冻结快照用于用户明确需要保留、对外引用、签核或复现的交付状态。初版、可运行、初步评审和等待试用本身不是冻结指令。用户明确要求保留的快照应保留，不以文件名或打分规则否定。

## 成果与对应关系

同一成果的新修订才是版本；不同报告/用途是不同成果线。只在有歧义时记录“成果 → 当前引用 → 状态 → 输入或相关成果”，复用现有索引。没有冻结交付物时，不强制填写空指针表。

状态描述可观察事实即可，例如“草稿，待业务试用”“已检查计算，待评审”；不要要求固定词表。分别表达实现/制作、AI 检查、用户确认和正式发布，避免混为完成。

关联关系按需要维护：Demo 与需求对应、报告与输入/处理对应、正式输出与批准状态对应。指针表中的相对路径以项目根目录为基准；普通 Markdown 链接仍按其文档自身位置解析。

## 保留历史，不破坏引用

新版本成为当前版时，只更新受影响指针。旧快照可留在原路径并标记已替代，不为目录整洁移动已被链接的文件；需要迁移时先评估引用和授权。

发现冻结成果错误，说明受影响结论及范围。在已有修订授权内创建新修订并保留旧版；缺少替换、撤回或重新发布权限时询问相应动作，不重新询问已授权的诊断与修正。

版本号服从项目现有语义及兼容性规则。一次普通迭代、一次用户反馈或一次文档同步，不自动要求升级应用、依赖或交付版本。
