# 里程碑与交接

仅在阶段验收、定稿、正式交付、发布、长期挂起、移交或项目结束时读取本文件。

## 进入里程碑的条件

至少满足一项：

- 产出从候选进入定稿或正式交付。
- 项目阶段或验收闸门发生变化。
- 结果将发布、部署、外发或交由他人继续。
- 项目将长期挂起或结束。
- 用户明确要求阶段收口、交接、验收或复盘。

普通功能完成、单项检查通过、一次会话结束或测试较多，不构成里程碑。

## 收口步骤

1. 读取启动卡或当前有效验收标准。
2. 逐条核对可观察证据，区分已验证、未验证、失败和不适用。
3. 发现未达标项时先报告，不擅自修改已冻结交付物；请用户选择补做、降级、顺延或接受风险。
4. 核对冻结交付物的唯一当前版、状态、历史位置和跨线关系。
5. 核对开放决策、风险、阻塞、授权和外部依赖。
6. 执行与风险相称的完整验证，并声明验证边界。
7. 更新 README 当前状态、冻结交付物指针和必要的里程碑记录。
8. 仅在确需长期保存证据时生成独立验收材料。

可运行：

```text
python scripts/health_check.py 项目根 --level milestone
```

若权威源含“禁用词｜应使用”表且本次改变相关定义，再运行：

```text
python scripts/check_terms.py --authority 权威源 --target 当前产出
```

## 交接

用户提出交接、执行者更换或项目长期挂起时，从当前事实现场汇编：

- 项目目标与当前阶段。
- 已完成结果与当前冻结交付物。
- 当前有效的权威源和关键约束。
- 开放待办、待确认、风险与阻塞。
- 最近必须知道的关键决策。
- 验证边界与尚未取得的证据。
- 下一位执行者可直接开始的第一步。

交接文档不常驻重复维护。README 与台账足够清楚时，直接输出交接摘要或按用户要求保存。

## 项目收尾

- 对照验收标准确认最终状态。
- 标记唯一终版或明确没有冻结交付物。
- 保留未完成、降级和顺延项，不把它们改写成已完成。
- 按需归位可复用资产；移动到共享资产库前确认位置和权限。
- 仅在用户要求、项目跨度较长或确有复用价值时读取 `references/复盘模板.md` 生成复盘。
- 不将单次反馈推断为长期偏好，不将缺失证据补写成事实。
