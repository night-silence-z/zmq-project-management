# 场景与反例

使用这些例子校准治理模式，不要把例子中的领域词写成通用规则。

| 场景 | 模式 | 应做 | 不应做 |
| -- | -- | -- | -- |
| 修正文档错字、调整局部样式、清理既有结构 | 轻量日常迭代 | 读直接相关文件并验证结果 | 更新 README、落进展流水、升级计划版本 |
| 在既定分析口径下补充一张图表 | 轻量日常迭代 | 校验数据与图表 | 因新增文件执行阶段收口 |
| 改变样本排除规则或指标定义 | 项目基线变化 | 更新唯一权威源和一条决策 | 在多个材料复制完整定义 |
| 改变活动范围、研究方法或交付受众 | 项目基线变化 | 写清旧→新→原因→影响 | 自动生成验收文档或关闭阶段 |
| 方案依赖尚未确认的许可、账号、预算或外部数据 | 项目基线变化 | 先核验可行性，再决定是否投入 | 先完成整套实现再验证条件 |
| 高影响但仍属既有范围内的修复 | 轻量日常迭代＋强化验证 | 扩大验证范围并声明边界 | 因测试较多自动升级为里程碑 |
| 正式报告定稿、成果发布或阶段验收 | 里程碑收口 | 对照标准、核对版本与证据 | 只因会话结束而执行同等流程 |
| 更换执行者或长期挂起 | 里程碑收口 | 生成最新交接摘要 | 常驻维护重复的交接文档 |

## 常见误判

### 把耗时当成模式

任务耗时长不等于里程碑；耗时短也可能改变项目基线。按影响判断，不按分钟数判断。

### 把验证强度当成治理模式

强化验证只说明失败代价高，不说明项目状态跨越正式关口。

### 把所有可阅读文件当成交付物

执行清单、README、台账和权威定义通常是活文档；只有冻结、独立验收和需要回退的材料才进入版本线。

### 把记录完整理解为记录一切

可交接依赖关键决策、风险、阻塞、当前状态和版本关系，不依赖每次普通进展的流水。

### 把一致性理解为到处复制

一致性来自唯一权威源和明确指针，不来自在 README、计划、台账和验收材料中重复同一句定义。
