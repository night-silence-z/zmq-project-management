# 启动与接管

仅在新建长期项目、用户明确要求建档，或接管已有项目时读取本文件。

## 新项目立项

先确认项目是否值得建档。若工作一次即可完成且无需后续接续，直接执行，不创建治理结构。

需要建档时，逐轮收敛三要素：

1. 最终交付什么形态的结果。
2. 谁会使用，以及用来做什么。
3. 如何通过可观察证据判断完成。

每轮最多问三个问题。能给选项时给出“选项＋推荐”；用户说“先开始”时停止追问，将缺口写为待确认并进入执行。

收敛标准：

> 本项目交付 X，给 Y 用来 Z，验收标准为 W。

同时明确：

- 本期做什么。
- 明确不做什么。
- 什么内容顺延，以及触发条件。
- 已知约束、风险和外部依赖。

按 `assets/templates/启动卡.md.tmpl` 生成启动卡并写入 `00_管理/README.md`。用户确认后冻结原始启动卡；后续变化通过基线决策记录，不改写历史承诺。

## 建立最小结构

优先运行：

```text
python scripts/init_project.py 项目名
```

默认只创建有内容的管理文件，不预建空的输入、产出、验收或归档目录。产生第一份材料时再创建对应目录。

建议结构：

```text
00_管理/
  README.md
  台账.md
01_产出/        # 出现冻结交付物时创建
02_输入/        # 需要集中管理输入材料时创建
99_归档/        # 出现废弃整线或一次性材料时创建
```

不要强制已有项目采用编号或中文目录。已有清晰结构时，记录实际位置即可。

## 项目自举

在适用的规则入口中只保留一行指针：

> 本项目使用 zmq-project-management；默认采用轻量日常迭代，仅在项目基线变化或里程碑关口时升级治理动作。

不要复制技能全文，也不要写成“每次会话必须完整读档和收口”。

## 存量项目接管

1. 先只读盘点，不移动、不重命名、不覆盖文件。
2. 列出现有目录、活跃工作文件、冻结交付物、疑似当前版、权威源、开放决策和明显缺口。
3. 多个疑似当前版并存时，给出候选、证据与推荐，交用户裁决。
4. 不虚构历史；缺失信息标记“待查”或“来源不明”。
5. 仅在现有结构确实妨碍继续工作时提出重组方案。
6. 批量移动、重组或删除前取得确认，并保留可回退路径。
7. 接管完成后进入轻量日常迭代，不持续执行接管级盘点。

## 启动阶段的反过度规则

- 不为尚未出现的材料创建空目录。
- 不为每类可能产出预设产出物线。
- 不在用户已提供清晰目标时重复立项访谈。
- 不将一次性任务强行升级为长期项目。
- 不因使用脚手架而要求用户手工填写模板；由 AI 根据已有信息生成。
