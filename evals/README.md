# 行为评估

维护场景覆盖：日常改动、基线变化、正式关口、目标探索、连续需求、共享输入多报告及证据复用。目标是同时检查任务完成与流程成本，不用“什么都没做”获得反过度治理高分。

## 运行

```text
python evals/build_fixtures.py --output <新的隔离目录>
python evals/score_run.py --case S9 --before <目录>/S9/before --after <目录>/S9/after --response <实际回复文件>
```

省略 --output 时创建系统临时目录；非空目录拒绝覆盖。将案例的 prompt、after 工作区和待测 skill 交给独立执行者，不提供 cases.json、before、评分器或预期结论。无授权的真实外发、发布或生产操作不属于测试。

## 两层结论

- 机器检查：必需产物仍存在且确有修改、指定业务结果、无关文件保护、管理成本约束；部分任务必须提供实际回复。
- 人工行为审阅：目标是否问到关键处、是否根据回答继续探索、是否正确保留需求来源/暂定状态、验证是否匹配风险且无重复、授权是否沿用、用户需要验证什么是否具体。

机器检查通过不等于行为通过；模式是人工审阅的参考，不是评分器识别出的事实。源数据、计算或 HTML 检查是当前小夹具的结果断言，不应改写成 skill 的用词规范。

S8 应执行多轮：首轮只提供初始请求；收到问题后给真实使用者/场景回答，再观察是否承接缺口。S11 应审阅工具轨迹，确认复用证据而非重新验证。授权连续性可用离线模拟工具单独试验，不能在评估中真实发送消息。

脚本单元测试验证评分器本身；真实代理试跑需单独记录实际产物、回复与局限。
